Streamlines · SCIRun ⇄ VTK
An explainer · visualizing current density

Following the current

When the quantity you care about is current density, the clearest picture of current is a streamline. SCIRun and VTK can both draw streamlines, but they store the geometry very differently. This page covers how each one works, where they disagree, and what we should build.

01 · The question

Arrows show direction. Streamlines show where current goes.

Between two electrodes, J = −σ∇φ. A glyph per point answers "which way here?". A streamline integrates those directions into paths, which answers "where does the current from this electrode end up?".

dipole · |J| colormap

What the viewer needs

Glyphs near an electrode are a blur of long arrows. Far away they are short and easy to miss, and you have to connect them in your head. A streamline does that connecting for you: one continuous path per seed, colored by |J|.

SCIRun module: GenerateStreamLines. Inputs: a vector field and a seed point set. Output: a field on a CurveMesh.

02 · Tracing one line

Each streamline is a numerical integration

Start at a seed and take a step along the field, then another. The method controls how fast the error builds up. Here the exact answer is a circle (field v = (−y, x)), so any drift is visible.

rotation field · 2 revolutions

SCIRun's five methods

AdamsBashforth, Heun, RungeKutta (RK4), RungeKuttaFehlberg (adaptive RK4/5, the default), and CellWalk.

Euler is not an option in SCIRun. It is shown here as the worst case. Drag h up and watch Heun leave the circle while RK4 and RKF stay on it.

CellWalk is different in kind. It steps element by element through a cell-centered (order-0) field rather than interpolating. It is also the method with an open stability bug, #872. Remember that for chapter 06.

VTK's equivalent

vtkStreamTracer offers RK2, RK4, and adaptive RK4-5, with termination reasons, integration time and vorticity as output arrays.

03 · Building the node list

Backward, reverse, forward

With direction set to Both, SCIRun integrates backward from the seed, reverses that list, then integrates forward and appends. At that point the algorithm holds the whole streamline as one ordered array. Watch the last step: writing the array to the output field keeps the points and the edges, but not the fact that they form one line from one seed.

Then setOutputData() walks this array, calls add_node for each point and add_elem({n1, n2}) for each consecutive pair, and moves on to the next seed. Nothing in the output marks where one streamline ends and the next begins. Chapter 04 shows what that costs.

05 · What the VTK renderer does today

Rebuilding lines SCIRun already knew

VtkGeometryBuilder::addStreamline receives an edge list and needs polylines to give vtkTubeFilter. It recovers them with a graph search. This runs for every CurveMesh that reaches the VTK renderer, not only streamlines.

  1. Copy points + scalars.
    facade->nodes() → vtkPoints, "Values"
  2. Collect every edge.
    facade->edges() → EdgeVector
  3. Find connected components.
    boost::connected_components
  4. Order each component.
    undirected_dfs + FindPath()
  5. One vtkPolyLine per component.
    lines->InsertNextCell(polyLine)
  6. Tube it.
    vtkTubeFilter · 16 sides

At a node with three or more edges, FindPath skips the third edge and everything behind it (the source says // TODO: deal with branching streamlines). GenerateStreamLines never produces branches, but other curve meshes such as wire networks and electrode leads can.

06 · Scorecard

CurveMesh vs. VTK polylines

VTK has no special "streamline" type. vtkStreamTracer produces a vtkPolyData whose cells are vtkPolyLines. That is the native type we are comparing against.

SCIRun CurveMeshVTK vtkPolyData polylines
Connectivity● A flat list of 2-node edges, with no concept of "a line"● One cell per streamline, with an ordered point list
Line identity● Lost at creation and recovered by a graph search● Built in: cell id, plus a SeedIds array
Per-point data● One scalar per node (the StreamlineValue option)● Any number of named arrays
Curved segments● The basis supports higher order, but streamlines use linear● Straight segments only
Memory● Node table + edge table● Points + cell array; about the same
Works with the rest of SCIRun● Every Field module: probe, map, clip, save, Python● Only the VTK renderer
Branching curves● Representable (a node can have three edges)● Must be split into separate cells

Verdict

Don't switch data types. A CurveMesh can hold everything a polyline holds, and switching would cut streamlines off from every Field module.

The real gap

The gap is one missing fact: which nodes make up which line. The algorithm knows it while tracing and drops it on output.

07 · Current in tissue

Current bends at tissue boundaries, and thin layers are hard

At an interface, normal J is continuous and tangential E is continuous, so tan θ₂ = (σ₂/σ₁) · tan θ₁. In a FEM solution J is usually per element (order 0). If you interpolate it to nodes before tracing, a thin layer such as skull is blended with its neighbours, and the streamline shows current flowing along the layer where it should cross it.

outer · thin layer · outer
Presets:

Two ways to trace

- - dashed: exact, element by element on order-0 J. This is what CellWalk is for.

solid: J averaged to nodes, then interpolated and integrated with RKF. This is the path you get from the default settings.

What this means

  • Trace J = −σ∇φ, not ∇φ: compute the gradient, then weight it by conductivity.
  • For order-0 J through thin layers, the accurate method is CellWalk. It is unstable (#872), so fixing it comes before new streamline features.
  • Drag "elements across layer" up: refining the mesh shrinks the smeared zone, but the elements touching each interface stay wrong.
  • In this flat toy the solid lines still exit at the right height, because node averaging conserves the total. In a curved head the errors are not guaranteed to cancel.

The conductivity ratios are illustrative values from the literature (scalp ≈ 0.33 S/m, skull ≈ 0.01, CSF ≈ 1.65). This 2D toy has straight interfaces, so the real head will look different.

04 · DECIDE

vtkStreamTracer?

Wrap VTK's tracer only if RKF turns out to be the weak point. It brings termination reasons, integration time and vorticity, at the cost of a field-to-vtkUnstructuredGrid conversion.
